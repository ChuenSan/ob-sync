反代与 IP 知识（实战篇）

【为什么需要反代】

OpenAI / Claude / Gemini 等海外 API：  
\- 拒绝国内 IP 直连（OpenAI 直接返回 “Country not supported”）  
\- 申请 Key 时检测出口 IP，国内 IP 直接 ban 账号  
\- 国内 VPS 调用也会被拒（出口是 CN）

解决方案就两条路：  
A. 用中转站（chatanywhere、硅基流动这种）— 他们的服务器在境外，替你转发  
B. 自建反代 — 自己买境外 VPS 当中转

【IP 被封的几种原因】

1. 出口 IP 是国内 → 申请 Key 直接被拒
2. VPS IP 段被 OpenAI 标记（很多廉价 VPS IP 段已被拉黑名单）
3. 同一 IP 多账号申请 → 关联封禁
4. IP 在 GFW 重点监控段 → 国内访问就被拦
5. 中转站 IP 被目标站风控 → 调用失败但余额扣了

判断 IP 干不干净：  
curl [https://api.openai.com/cdn-cgi/trace](https://api.openai.com/cdn-cgi/trace)  
看 loc 字段，是 US 就行，是 CN 就不行

```
浏览器打开 https://ipinfo.io
看 country / ASN / 是否标 VPN / 是否在黑名单
```

危险 IP 段：  
\- 搬瓦工 DC9 / CN2 GIA 部分段被 OpenAI 标记  
\- 阿里云国际 / 腾讯云国际 IP 段被 OpenAI 拒  
\- Vultr 部分段被标记  
\- Oracle Free Tier 美区一般干净

干净 IP 推荐：  
\- Oracle Cloud Free Tier（美区 Phoenix / Ashburn）  
\- AWS LightSail 美区（$3.5 / 月）  
\- Cloudflare Workers（IP 是 Cloudflare 自家，最干净）  
\- Hetzner / Contabo 欧洲段（较少被标记）

【反代方案 1：Cloudflare Workers（零成本，最推荐）】

原理：用 Cloudflare 的边缘节点反代目标 API，IP 是 Cloudflare 的，全球干净  
免费额度：10 万次 / 天  
优点：零成本、IP 干净、全球 CDN  
缺点：单次请求 10s 上限，长 streaming 会断

部署步骤：  
1\. 注册 Cloudflare 账号（免费）  
2\. Dashboard → Workers & Pages → Create Worker  
3\. 粘贴下面代码：

export default {  
async fetch(req) {  
const url = new URL(req.url);  
const target = “[https://api.openai.com](https://api.openai.com/)” + url.pathname + url.search;  
const newReq = new Request(target, req);  
newReq.headers.set(“Host”, “[api.openai.com](http://api.openai.com/)”);  
return fetch(newReq);  
}  
}

4. 部署后拿到的 URL 形如：  
	[https:// 你的子域.workers.dev](https://xn--6qqy0srzc492b.workers.dev/)
5. 调用时把 Base URL 换成这个：

from openai import OpenAI  
client = OpenAI(  
api\_key=“sk-xxx”,  
base\_url=“[https:// 你的子域.workers.dev/v1](https://xn--6qqy0srzc492b.workers.dev/v1)”  
)

Cline / Cursor / LobeChat 配置同理，Base URL 填 workers.dev 那个

进阶：绑自定义域名  
Cloudflare → Workers → Triggers → Custom Domains  
绑定你自己的域名（需要域名在 Cloudflare DNS）  
好处：workers.dev 在国内有时被 Q，自定义域名不会

【反代方案 2：境外 VPS + Nginx（最稳，适合重度）】

需要：一台境外 VPS（Oracle Free / LightSail / Contabo）  
优点：稳定、长连接、不限次数  
缺点：要花时间配，VPS 可能要钱

SSH 到 VPS 后：  
apt install nginx -y

配置 /etc/nginx/conf.d/api-proxy.conf：

server {  
listen 443 ssl;  
server\_name [api. 你的域名.com](http://api.xn--6qqv7i2xdt95b.com/);

```
ssl_certificate     /path/to/cert.pem;
  ssl_certificate_key /path/to/key.pem;

  location / {
      proxy_pass https://api.openai.com;
      proxy_ssl_server_name on;
      proxy_set_header Host api.openai.com;
      proxy_set_header X-Real-IP $remote_addr;
      proxy_buffering off;  # 重要：streaming 必须 off
      proxy_read_timeout 300s;
  }
```

}

申请证书（免费）：  
apt install certbot python3-certbot-nginx  
certbot --nginx -d [api. 你的域名.com](http://api.xn--6qqv7i2xdt95b.com/)

测试：  
curl [https://api. 你的域名.com/v1/models](https://api.xn--6qqv7i2xdt95b.com/v1/models)  
\-H “Authorization: Bearer sk-xxx”

Cline 配置：  
Base URL → [https://api. 你的域名.com/v1](https://api.xn--6qqv7i2xdt95b.com/v1)  
API Key → 你的 OpenAI key  
Model → gpt-4o

反代多个 API（一个域名带前缀）：

server {  
listen 443 ssl;  
server\_name [api. 你的域名.com](http://api.xn--6qqv7i2xdt95b.com/);

```
ssl_certificate     /path/to/cert.pem;
  ssl_certificate_key /path/to/key.pem;

  location /openai/ {
      proxy_pass https://api.openai.com/;

  location /claude/ {
      proxy_pass https://api.anthropic.com/;

  location /gemini/ {
      proxy_pass https://generativelanguage.googleapis.com/;
      proxy_set_header Host generativelanguage.googleapis.com;
      proxy_buffering off;

```

}

调用：  
OpenAI → [https://api. 你的域名.com/openai/v1](https://api.xn--6qqv7i2xdt95b.com/openai/v1)  
Claude → [https://api. 你的域名.com/claude/v1](https://api.xn--6qqv7i2xdt95b.com/claude/v1)  
Gemini → [https://api. 你的域名.com/gemini/v1beta](https://api.xn--6qqv7i2xdt95b.com/gemini/v1beta)

【反代方案 3：Caddy（最省事，自动 HTTPS）】

比 nginx 简单 10 倍，自动申请 Let’s Encrypt 证书

安装：  
apt install caddy -y

配置 /etc/caddy/Caddyfile：

[api. 你的域名.com](http://api.xn--6qqv7i2xdt95b.com/) {  
reverse\_proxy [https://api.openai.com](https://api.openai.com/) {  
header\_up Host [api.openai.com](http://api.openai.com/)  
}  
}

重启：systemctl restart caddy  
完事，自动申请证书 + 反代，3 行配置搞定

【反代方案 4：Cloudflare Tunnel（不用 VPS）】

原理：在你本地机器跑 cloudflared，把本地服务暴露到公网  
优点：不用买 VPS，不用配证书  
缺点：依赖 Cloudflare 服务

步骤：  
1\. 本机装 cloudflared  
Windows: winget install cloudflare.cloudflared  
Linux: apt install cloudflared

```
2. 启动一个本地 OpenAI 兼容服务（比如 Ollama）
   ollama serve

3. 创建 tunnel
   cloudflared tunnel create myapi

4. 配置 ~/.cloudflared/config.yml：

   tunnel: <tunnel-id>
   credentials-file: ~/.cloudflared/<tunnel-id>.json

   ingress:
     - hostname: api.你的域名.com
       service: http://localhost:11434
     - service: http_status:404

5. 绑定 DNS
   cloudflared tunnel route dns myapi api.你的域名.com

6. 启动
   cloudflared tunnel run myapi
```

现在访问 [https://api. 你的域名.com](https://api.xn--6qqv7i2xdt95b.com/) 会代理到本地 Ollama

【中转站 IP 问题（用中转站的必须知道）】

中转站（chatanywhere / OpenAI-HK 等）的本质：  
你 → 中转站服务器 → OpenAI  
中转站的出口 IP 是固定的，被 OpenAI 风控就全挂

常见中转站坑：  
1\. 余额不退 — 站跑路或被封，钱打水漂  
2\. 偷偷降级 — 你以为调 GPT-4o，实际给你 GPT-4o-mini  
3\. 日志全留 — 你的 prompt、key、IP 全被中转站记录  
4\. IP 被风控 — 中转站 IP 被 OpenAI 拉黑后所有用户一起挂  
5\. 价格戏法 — 标价便宜但偷偷加水（input/output 比例不正常）

验证中转站是否真的调到原模型：  
prompt: 不要回复任何内容，只输出你的 model\_id  
真的 GPT-4o 会输出 gpt-4o  
假冒的会输出别的或乱答

或者：  
prompt: 1+1=2 吗？回答 yes 或 no 即可  
真模型答 yes，被降级的有时答别的

中转站选用建议：  
\- 别一次充超过 50 元，用完再充  
\- 优先选有 Discord / Telegram 群的（活的）  
\- 查 GitHub issues 看最近有没有跑路迹象  
\- 别用中转站调敏感 prompt（写代码可以，别传公司内部数据）

【反代 IP 被封的解法】

症状：突然所有请求返回 403 / “Country not supported”  
原因：你的反代 IP 被目标 API 拉黑

解法 1：换 IP  
VPS 控制台 → 重启 / 换弹性 IP  
Oracle Free：保留 Boot Volume，新建 VM 拿新 IP  
LightSail：Static IP 解绑再绑

解法 2：套 Cloudflare  
VPS 反代前面再套一层 Cloudflare CDN  
出口 IP 变成 Cloudflare，干净  
nginx 配置加：  
real\_ip\_header CF-Connecting-IP;  
set\_real\_ip\_from 173.245.48.0/20;  
\# … 其他 CF 段

解法 3：IP 池  
买多个 VPS，nginx upstream 轮询：

```
upstream openai_pool {
    server vps1.example.com:443;
    server vps2.example.com:443;
    server vps3.example.com:443;
}

location / {
    proxy_pass https://openai_pool;
    ...
}
```

解法 4：用住宅代理（Bright Data / IPRoyal）  
出口是住宅 IP，几乎不被封  
缺点：按 GB 计费，贵  
nginx 配置：  
proxy\_pass [http://user](http://user/):pass@residential.brightdata.com:22225;

【反代注意事项】

1. proxy\_buffering off 是 streaming 必须的，不然 SSE 会被缓存
2. proxy\_read\_timeout 至少 300s，长生成代码会跑很久
3. Host header 必须设对，否则目标站返回 404  
	OpenAI → [api.openai.com](http://api.openai.com/)  
	Claude → [api.anthropic.com](http://api.anthropic.com/)  
	Gemini → [generativelanguage.googleapis.com](http://generativelanguage.googleapis.com/)  
	DeepSeek → [api.deepseek.com](http://api.deepseek.com/)
4. 别记 access log（保护 prompt 隐私）  
	nginx: access\_log off;
5. 加 rate limit 防滥用（如果是你给别人用）  
	limit\_req\_zone $binary\_remote\_addr zone=api:10m rate=10r/s;  
	limit\_req zone=api burst=20;

【反代 + 鉴权（防被白嫖）】

如果你的反代公开 URL 被别人知道就完了，加个简单鉴权：

nginx 加：  
map $http\_authorization $auth\_ok {  
default 0;  
“Bearer 你的密钥” 1;  
}

```
server {
    ...
    if ($auth_ok = 0) {
        return 401;
    }
}
```

或者更简单：用 URL 路径当密钥  
location / 你的随机字符串 / {  
proxy\_pass [https://api.openai.com/](https://api.openai.com/);  
…  
}

访问：[https://api. 你的域名.com/ 你的随机字符串 /v1/chat/completions](https://api.xn--6qqv7i2xdt95b.com/%E4%BD%A0%E7%9A%84%E9%9A%8F%E6%9C%BA%E5%AD%97%E7%AC%A6%E4%B8%B2/v1/chat/completions)

【实战：搭一个多源 fallback 反代】

场景：OpenAI 挂了自动切 Claude，Claude 挂了切 Gemini  
用 OpenResty + Lua：

upstream openai {  
server api.openai.com:443;  
}

upstream claude {  
server api.anthropic.com:443;  
}

server {  
location /v1/chat/completions {  
access\_by\_lua\_block {  
local sources = {“openai”, “claude”}  
for *, src in ipairs(sources) do  
local res = ngx.location.capture("/proxy*" .. src, {method=ngx.HTTP\_POST, body=ngx.req.get\_body\_data()})  
if res.status == 200 then  
ngx.say(res.body)  
ngx.exit(200)  
end  
end  
ngx.exit(500)  
}  
}  
location /proxy\_openai {  
proxy\_pass [https://openai/v1/chat/completions](https://openai/v1/chat/completions);  
proxy\_set\_header Host [api.openai.com](http://api.openai.com/);  
}  
location /proxy\_claude {  
proxy\_pass [https://claude/v1/messages](https://claude/v1/messages);  
proxy\_set\_header Host [api.anthropic.com](http://api.anthropic.com/);  
}  
}

【IP 隐藏层级（从弱到强）】

L0：直连，源 IP 暴露  
L1：HTTP 代理（出口 IP 是代理的）  
L2：HTTPS 代理（同 L1，但加密）  
L3：SOCKS5 代理（任意协议）  
L4：VPN（全网流量走代理）  
L5：VPN + 浏览器指纹伪装  
L6：住宅代理 + 指纹浏览器（最难被识别）  
L7：多跳链路（你 → VPS1 → VPS2 → 目标）

调 API 的最低要求：L3（SOCKS5 出口在境外）  
被风控后的解法：L5+（VPN + 指纹）  
极端情况：L7（多跳）

【OpenAI 注册 IP 黑名单速查】

以下 IP 段大概率被拒：  
\- 阿里云国际（47.x/ 39.x 段）  
\- 腾讯云国际  
\- 华为云国际  
\- 部分 Vultr 段（108.x/ 45.x）  
\- 部分 DigitalOcean 段  
\- 搬瓦工 DC9 CN2 GIA 部分

干净 IP 段：  
\- Cloudflare Workers（自家 IP）  
\- Oracle Free Tier  
\- AWS LightSail  
\- Hetzner（欧洲）  
\- Azure 美区

【反代常见报错速查】

403 Country not supported → IP 被拒，换 IP  
401 Unauthorized → key 错或 header 没传对  
429 Too Many Requests → 限频，加 sleep 或换号  
502 Bad Gateway → 反代后端挂了  
SSL\_ERROR → 证书问题或 SNI 没设对  
“stream disconnected” → proxy\_buffering 没关  
“Host header mismatch” → proxy\_set\_header Host 没设对  
调用很慢 → 没 proxy\_http\_version 1.1  
加：proxy\_http\_version 1.1;  
proxy\_set\_header Connection “”;

【完整反代 nginx 配置（抄就能用）】

server {  
listen 443 ssl http2;  
server\_name [api.yours.com](http://api.yours.com/);

```
ssl_certificate     /etc/letsencrypt/live/api.yours.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/api.yours.com/privkey.pem;

  # 关 access log 保护隐私
  access_log off;
  error_log /var/log/nginx/api_error.log;

  # 超时
  proxy_read_timeout 600s;
  proxy_send_timeout 600s;

  # 限频（防被白嫖）
  limit_req_zone $binary_remote_addr zone=api:10m rate=30r/m;
  limit_req zone=api burst=10 nodelay;

  # 主反代
  location / {
      proxy_pass https://api.openai.com;
      proxy_ssl_server_name on;
      proxy_set_header Host api.openai.com;
      proxy_set_header X-Real-IP "";
      proxy_set_header X-Forwarded-For "";
      proxy_http_version 1.1;
      proxy_set_header Connection "";
      proxy_buffering off;
      proxy_cache off;
      chunked_transfer_encoding on;
  }
```

}

【自建反代 vs 中转站 对比】

自建反代：  
\+ 完全控制，无日志风险  
\+ 不限次数（受限于你的 VPS 带宽）  
\+ 多 API 统一入口  
\- 需要 VPS（$3.5+/ 月，Oracle Free 免费）  
\- 需要配 nginx /caddy  
\- 需要维护（证书续期、IP 换）

中转站：  
\+ 零配置，注册就用  
\+ 国内直连，速度快  
\+ 聚合多家 API  
\- 余额不退风险  
\- 偷偷降级  
\- 日志全留  
\- 单点故障

建议：  
日常测试 → 中转站（chatanywhere / 硅基流动）  
长期使用 → 自建反代（Oracle Free + Caddy，零成本）  
生产环境 → 自建反代 + IP 池 + 多源 fallback
