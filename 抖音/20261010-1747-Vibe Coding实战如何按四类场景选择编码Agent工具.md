# 速览

## 一句话主旨
按自动化程度，视频把 Agent 分成 IDE 人机协作、纯编码、办公和数字员工四类，强调按场景选、同类才可比。编码工具再分 CLI 与 GUI 做主观排序；讲述者看重 harness 是否够干净、能否自己改造，并认为数字员工所宣传的自进化，对个人生产力是陷阱。

## 核心要点
- 视频把主流 Agent 按自动化从低到高分成四类：IDE 里的人机协作编码，纯编码 Agent，包了界面和额外功能的办公 Agent，以及开箱带很多附加功能的数字员工。越往后越自动，但不代表直接选最后一类。具体产品最好同类相比，最多比相邻两类；Workbuddy 可以跟另一款办公产品比，不该和 Claude Code 或 Cursor 比。
- 第一类 IDE 加 Agent，讲述者不太看好，认为模型变强后需要人介入的场景会变少，有点像过渡产品。他觉得从 Copilot 的补全走到全自动并不久，工具迭代却从大约六年一代快到大约六个月一代。仍适用的是老项目、上下文只在人脑子里，项目重到难改、循环也难建，以及必须把结果和过程都留下来。
- 人机协作赛道里，Cursor 被放在 T0，讲述者说它长期被拿来和 Claude Code 横向对比，主要对手是 Windsurf 和一些国产 IDE。这些工具多由 VS Code 改造而来，有的扩展做得深，有的只是插件，能给 Agent 的能力范围他认为差别不大。能力优先选 Cursor，成本优先选国产工具。Zed 用 Rust 从零开发，摆脱了 Electron，更快，但不能用 VS Code 插件。
- 纯编码 Agent 分 CLI 与 GUI，不限于 Vibe Coding，生产和自媒体都能用。办公 Agent 与它重合，编码 Agent 更干净；讲述者坚持少就是多，只把办公类建议给非程序员的办公场景，并称国内做得较好。数字员工主打自主和自进化，企业可用来处理杂事，个人生产力要回到第二或第三类：上下文必须自己审核、只留最小数据，否则自动化是陷阱。
- 拆到具体产品时，视频说明 Agent 不像大模型有充足 benchmark，后面全是主观判断，不少工具讲述者也没深度用过，体验不同就以使用者自己为准。他同时呼吁第三方开源基金会或研究机构来做评测：固定模型，只换 Agent 跑用例，至少覆盖 harness 核心。
- CLI 下 Claude Code 在 T0。讲述者称其公司操作有问题，但 harness 有东西，同时又说 Codex CLI 略胜一手。这次外部 Coding 准备用 Pi：核心简单，定制放进配置和扩展，能自己改造，上限最高，但要折腾。OpenCode 不错，只是一部分场景被 Pi 占去，重心在 coding plan。GPT 套餐选 Codex CLI，喜欢 Zed 选 Pi，排斥前述公司就选 OpenCode，否则选 Claude Code。
- GUI 下 Codex 又是 T0，Claude 只到 T2，原因被说成众所周知。Z Code 被夸打磨用心，多数国内模型厂商的编码产品则被吐槽缺少打磨，没人力就别拿套壳上线。DeepSeek Harness 想法好，但还不稳定，暂排第二。小白开箱即用，他推荐 GPT 套餐加 Mac 加 Codex 桌面版；想折腾用 DeepSeek Harness，否则用 Z Code。办公 Agent 这期不推荐，下一期讲需求分解。
- 讲述者用 DeepSeek Harness 和 Pi 对照自进化，路径不同。Claude Code、Codex 是完整 harness；Pi 只给最小核心，像种子长成树；DeepSeek Harness 做成可插拔模块，像能拆开重拼的积木。Hermes、小龙虾那种自进化被说成记忆工程，要管上下文大小、聪明区和注意力，小白想要却不会管，长期是陷阱。Pi 则能改自己的样式、harness 和提示词，这与只会写 Skill 不同。官方并没有宣传能自进化。
