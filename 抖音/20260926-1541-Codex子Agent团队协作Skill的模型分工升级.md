# 速览

## 一句话主旨

视频介绍了 Codex Team 协作 Skill 从 GPT-5.6 到 GPT-6 的升级：合并执行角色、保留探索与审查角色、增加 Expert Advisor，并集成 Explore 与 Simplify 规范，通过按任务复杂度选择是否委派子 Agent，在成本、速度和执行质量之间进行平衡。

## 核心要点

- 旧版 Codex Team 将角色分为探索者、简单代码实现者、复杂任务实现者和审查者，并为不同角色配置不同模型，主要目标是降低高成本主模型的调用开销、提升部分任务的执行效率。
- 新版将模型整体升级到 GPT-6：探索者使用 GPT-6 Luna 并默认开启 Fast 模式；简单代码和复杂代码实现者合并为一个 GPT-6 Luna、High 思考程度的执行者，负责大多数日常任务。
- GPT-6 Luna 更适合边界清楚、目标明确的任务，但在复杂项目中的规范触发、细节理解和指令遵循方面不如更高档次模型，因此需要由主 Agent 明确告知执行目标和规范位置。
- 审查角色升级为 GPT-6 Sol，提示词针对代码过度复杂、组件化和函数化不足、重复实现已有库能力，以及可维护性差等问题进行了预置优化，并降低了内置提示词的复杂程度以提升通用性。
- 新增 Expert Advisor 角色，使用成本更高但更聪明的 GPT-6 Astra，在任务反复解决不好、问题过度复杂或需要提前设计复杂功能方案时提供建议。
- Skill 不会对所有任务强制派发子 Agent，而是先判断任务复杂度；简单任务由主 Agent 直接完成，复杂任务才调用子 Agent。
- Explore 规范要求在修改复杂代码仓库前先了解仓库整体结构并定位相关代码；Simplify 规范用于大批量编码完成后或提交前，从实现质量、复用性等角度并行审查。
- Skill 可通过 `/wm` 主动触发，也可能在复杂或多仓库项目中自动触发；配套脚本能够查看不同模型的用量，视频还提到将标题自动命名 Skill 升级为 GPT-6 Luna 以降低开销。

# 视频原文

Hello大家好，最近随着GPT-6新模型的推出，团队协作的Skill叫做Codex Team，做了一个升级。
上一版：四类角色对应不同配置。首先给大家介绍一下Skill，是在Skill里面维护了4个不同的角色，使用的是不同的模型。一个是探索者，使用的是GPT-5.6LunaMedium；一个是简单代码的实现者，使用的是GPT-5.6LunaMedium；还有一个是复杂任务的实现者，使用的是GPT-5.6TerraHigh；最后还有一个Culturalr负责审查，代码实现使用的是GPT-5.6Sol High模型。Agent默认沿用主模型。
之所以之前会实现团队协作的Skill，目的是为了降低Codex的使用成本，以及提升部分任务执行效率。在之前的Codex版本里面，如果想要让GPT去派发不同模型的子Agent，是需要提前把这些子Agent的配置文件给创建好的。如果没有提前创建好，默认分发的是跟主Agent的模型一样的。之前可能用GPT-5.6Sol的开销很高，如果再派发子Agent也是，其实起不到降低成本的作用。所以会发现使用Ultra模式去启动子Agent。
新版分工：不同任务找不同角色。在最新的版本里面把Skill做了哪些调整？首先是所有的模型都升级到GPT-6的版本，探索者依然是使用GPT-6Luna模型。除此以外还可以设置速度，默认设置了Fast模式。因为GPT-6Luna的价格比GPT-5.6Luna还要便宜60%，所以开Fast模式可以更快地帮助AI Agent定位需要修改的代码位置。
这里移除了简单代码和复杂代码实现者两个角色，合并成了一个简单的执行者，就是GPT-6Luna，使用的是High的思考程度，负责大多数的日常任务的执行。因为经过前段时间重度使用GPT-5.6Luna的经验，GPT的Luna模型其实执行任务效果还是不错的。但是自己会发现GPT-6Luna有时候表现的还不如GPT-5.6Luna，但没办法，GPT-6Luna实现边界清楚的任务价格实在是太便宜了。所以如果给它派发的任务非常明确，使用执行者效果也是不错的。
它的一些不足之处在于什么？相较于更强档次的模型，最明显的问题就是Skill的触发，或者如果复杂项目里面存量的规范比较多，就没有那么细致，指令遵循性没有那么强。因为有些规范要求它去读的，没有明确的说到就不会去读。但是作为子Agent去使用，很多时候主Agent的模型已经告诉具体要去读了哪个规范，在执行什么任务了，用来执行任务效果就还不错。
然后Culturalr也没有大的调整，只是把GPT-5.6Sol升级为了GPT-6Sol，还是用来检查代码实现的怎么样的。因为觉得Culturalr的角色还是很重要的，因为很多时候第一次就是写不好，需要再去review的时候才能够发现一些问题。这一次Culturalr的提示词也对应的有一些优化，就是针对GPT很喜欢写门禁问题、代码过度复杂这些问题或者没有做很好的组件化、函数化的问题，以及没有利用现有的库，而是自己去手搓很复杂的代码，导致代码可维护性很差。这些都提前预制在了Culturalr的系统提示词里面，自然在review的时候就天生会有一个比较好的方向。
还有就是相比于之前的版本，明显的降低了它里面内置提示词的复杂程度。因为之前写的一些交付的产物写的有点复杂了，太细致了，这就导致GPT模型在review时更容易钻牛角尖，总要看一些特角旮旯写的报告也可读性很差。优化了它的提示词之后可以提升它的通用性，因为很多时候可能review不仅仅是用于这种代码仓库里面的，做个PPT或者做一些调研去review也是可以用的。
除了以上的3个Agent之外，还新增了一个角色叫做Expert Advisor，它就相当于一个给出建议的专家。因为GPT-6的模型的架构调整了一个价格明显更贵的模型，日常使用开销是很高的。正常来说使用GPT-6 Astra作为主Agent驱动模型就好了。什么时候使用GPT-6 Astra？优先把它作为了一个内置角色，就是作为一个更加聪明的角色。当遇到反复解决不好的任务或者过度复杂的问题就可以请教GPT-6 Astra，或者在执行一个复杂功能之前可以让GPT-6 Astra来写一个方案。这个理念其实参考Claude里面有一个Advisor API，它的作用是以前用Sonnet模型的时候，如果有些任务太复杂一直执行不好，可以去请教Opus模型，可能会去请教Fable模型。
任务来了，先判断要不要委派。Skill里面不是一定要用Skill就一定会去派发子Agent的，还是会去判断要不要委派的。假设一个非常简单的任务，那么它就直接自己做了，就没有必要再去启动子Agent了。只有任务是带有一定复杂度的才会去调用子Agent。
Explore在前，Simplify在后。除了角色的调整Skill里面还新增了两个额外的文档规范，一个是Explore，还有一个是Simplify。这两个其实以前都是单独的Skill，这些也是从Claude里面来的一些内置Skill，把它集成到了现在Skill里面去作为一些规范。
Explore就是每次在看一个新的复杂代码仓库之前可以先派发子Agent去对对应的仓库做一个整体的了解，然后再找到本次需要修改的具体的代码位置，返回给主Agent告诉你要看的是哪几个代码，这就是探索代码的Explore在前。
另外一个Simplify就是每次写完一大批代码之后或者在提交代码之前可以有个系统性的review，可以并行几个子Agent，针对不同的角度去进行review，比如实现的质量以及代码的可复用程度。
Skill安装之后其实它的使用也很简单，可以直接斜杠wm，这是主动触发。有的时候如果发现仓库比较复杂，比如多子仓库的或者代码仓库比较多一些，那么就会自己去触发Skill了。
Skill其实还提供了一个查看用量的脚本，就是可以去看不同配比这些模型大概消耗了多少用量。比如这里触发Skill之后，默认使用最高权限OPT-6GPT-5.6模型比例，跟他说查看一下最近一个月不同模型的用量发送给他。这里可以看到如果触发了Skill，会很明显的告诉你已开启小队模式，还带有一个emoji，这样子就知道Skill是否准确触发了。这里就可以看到最近一个月的用量了，大概消耗了90几亿的，不同的模型消耗额度都可以看到。
用最近用的最多的就是GPT-6Astra，然后就是GPT-5.6Sol，但是相同的token数量，GPT-6Astra会比GPT-5.6Sol贵很多，这里开销高很多。GPT-5.6Luna和GPT-6Luna用量其实也不少，也有十几亿，这里也有5亿，但是消耗甚至1%都不到，所以这两个模型开销是非常非常低的。我也很推荐大家去使用这两个模型，这里有一个Skill，这个帮助去给Codex的标题自动化命名的Skill，我也把它升级到了GPT-6Luna，因为开销更低了。可以看到现在左侧这些很规整的标题非常方便区分的就是Skill自动帮我做的，这个也非常推荐大家去安装一下，很实用的。
