# 速览

## 一句话主旨
这期给 Pi 配上 general、explore、review：探索用大上下文便宜模型，审查换提供商，改动写进自己的说明而不是 skill。再按 wayfinder 的阻塞跑完工单，探索交给子代理，质询跟实测，汇总票用 handoff 接后补事实。

## 核心要点
- Pi 默认不带 subagent。视频推荐一个极简扩展，口播像「PA萨light」，把提示词贴进 Pi 回车即可，装好后有命令和文档。默认是 general 和 explore；配合 Matt Pocock Skills 再加一个给 code review 用的 review，平时这三个就够。配置时把官方文档地址交给主 agent，并说明用途。
- general 沿用主 agent 的当前模型。explore 很烧 token，换成大约一兆上下文的便宜模型；讲述者用已有套餐里的 MiniMax M3，上一代也可以。review 必须换提供商，VIVO 2.6 不适合审 VIVO v2.6 Pro，换成哪款口播没说清。后文也把主力模型说成 MiMo v2.6 Pro。
- 模型要改 code review 的 skill，被打断。技能包更新勤，手改会在 `npx skills update` 时被覆盖，所以写进自己的说明，口播先后像 AGENTS.md 和 edit.md，并写清何时调哪个 subagent。research 先调 explore，装上 Playwright 后再加它的 MCP。说明只写要做什么。当时四十多行，加完可能约八十行，再用口播里的 Writing for engines 精炼。
- 上一期地图有 5 张工单，类型包括原型、咨询和探索。探索无阻塞，task 也能直接跑；03、04 被 02 挡住，05 被 02、03、04 挡住。于是 01 走 research，并另开窗口做 02。02 没有具体实现，就不走偏重的 TDD 加审查，直接用提示词。01 的回答写进文档，大部分成立，也有小问题和待实测项。
- 探索不要放在主 agent 里，无用上下文会挤占聪明区；派 subagent，只把总结交回来。01 的 explore 用的是 MiniMax M3。02 堵住后面三张，再给 7 分钟，做不完就第二天。讲述者认为这套 skills 要人半自动调控，质量更稳；Superpowers 定完可以放着跑。赶时间更建议 DeepSeek V4.1 Flash。
- 第二天 02 给出规格假设的实测，有的成立有的不成立，才开 03、04。旧窗口上下文大约只有 5.5% 也建议新开。03 被说成原型实验，04 被说成质询；结果若写入规则文档，就不走 grill-with-docs，口播是 great do，而直接用视频里的 green。和文档冲突时遵循 01、02 的事实，修正按推荐采纳，因为这是在改文档，不是对齐偏好。
- 后文又把待裁定的原型称作 04：脚本越大注入越少，多数情况 runner 更好，于是保留 runtime runner。新开的 06 只被 02 挡住，可以先做，05 还要等 04。06 里不靠探索的题按推荐答，包括异常被脚本吞掉后还记不记次数。探索后来能直接读到内存用量，冲突项可以同时满足：超限只发生一次，不会内存泄漏，建议用更轻量的做法。
- 05 是汇总票，阻塞可能没画对。模型说不必等 06，讲述者仍要求等：06 会改长文档中段，只看回答读不到，要用 handoff。05 还建议改名，并确认口播里的 KDS 没问题。本轮从 5 张变成 6 张后全部关掉。决策单独开成 ADR，HLD、SLD 只留指针，不复制决策。追结果用这款 v2.6 Pro，追速度用 DeepSeek V4.1 Flash。下一目标是规则设计，视频不带着做。
