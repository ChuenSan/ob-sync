# 速览

## 一句话主旨
面试中介绍的智能诊断智能体，用五层架构处理研发交付里的构建、部署、流水线和机器异常，并通过多版本 MCP 路由接入外部工具。部分运行时问题已能自动发现，诊断和方案提出已落地；讲述者称结合全链路监控与裁判模型后，十分制综合分约为八分多。

## 核心要点
- 智能诊断要减少构建失败、部署失败、流水线失败和机器异常的人工排查，初中级工程师往往无从下手。目标分为自动发现、智能诊断与方案提出、自动修复及线下环境部署；目前部分运行时问题已能自动发现，诊断和方案提出已落地，自动修复仍在规划。
- 架构分五层：接入层负责指令识别、增强和安全防护；编排层负责规划、工具渐进披露，以及可插拔 MCP 与 Skill 热加载；执行层负责编排、工具执行和二级披露；治理层负责模型调用、沙箱和全链路日志；资源层存储用户与规划数据。讲述者负责架构和核心模块。
- 用户指令既有自然语言，也有文档、图片和语音。语音使用 SR、PDS 等模型，日志类文档逐行提取关键信息。图片先用更便宜的 OCR 做全量识别，能得到关键信息就直接使用；信息散乱、带平台标识，或用箭头、方块指向问题时，再用更贵的视觉模型理解。
- MCP 在订阅时记录协议版本，镜像预置各版本客户端，加载时按版本路由，以避免新客户端调用旧协议报错。Skill 被描述为天然可插拔。沙箱全生命周期和 Supervisor 模式也被列为亮点，但没有讲具体做法。
- 质效团队向产研和 SRE 提供该能力，测试、自测和线上都可排查。构建与部署失败来自公共账号所搭环境的 MQ；运行时异常只看上线流程内服务的错误日志，诊断后给出根因、方案和 PR。机器异常等还不能自动发现，计划再监听 COE、SRE 平台消息。
- 2025 年从 Python、LangChain 迁到 Spring AI Alibaba。讲述者的理由是 Java 栈能衔接旧系统、团队不必集体学 Python，复杂编排和中间件集成更好，并认为定制化强于 LangGraph。若现在重选，大约八成仍会选用它。
- 评测使用约一百多条自愿反馈，以及约一千多条兼作意图识别的运维、FAQ 和失败案例。裁判模型比较预期输出和实际输出；线上指标含召回率、准确率、重规划次数、步骤准确率、调用异常和耗时。讲述者称已上生产，十分制约八分多，每周自动评测并抽检一至三成。
- 重要性中等的需求先把 PRD 收成清晰规格，再让 AI 按规格写代码并人工抽查；探索和边缘场景可以全程使用 AI。规格驱动尚未推广到全组，领导担心双重维护成本，集团则希望做法更多元。跨项目复用须全员执行，规格随代码版本提交，并参照代码合并处理冲突。
