# 速览

## 一句话主旨

视频解释上下文窗口并非越大越好，超长输入可能带来注意力稀释、位置偏移、成本上升和幻觉等问题，并从任务类型出发介绍小窗口、分片检索、记忆压缩、滑动窗口和分段推理等工程优化方案。

## 核心要点

- 上下文窗口是模型单次输入与输出可容纳的最大 Token 总量，但窗口容量不等于有效记忆能力；短问答、长文档和多轮对话应选择不同窗口策略。
- 超长上下文可能出现注意力稀释、位置偏移、首尾遗忘和中间内容错乱，关键信息反而可能被大量文本淹没，导致准确率下降。
- 长上下文还会增加显存、推理耗时和调用成本，并可能因冲突或模糊内容增多而提高幻觉风险；视频提醒不要仅靠堆叠窗口长度解决问题。
- 短任务和高频问答适合小窗口高速模型；长文档解析、合同审核和代码分析可以使用适量大窗口，但应配合分片与重排；知识库问答优先使用 RAG 过滤相关片段。
- 多轮对话可以采用滑动窗口和记忆摘要，保留有效内容、淘汰无效历史；超长文档可以分段推理并融合结果，降低上下文偏移和稀释的影响。
- 视频总结的工程取舍是“够用即可”：根据任务在分片、压缩、精准定位和成本延迟之间平衡，而不是无脑使用超长上下文。
