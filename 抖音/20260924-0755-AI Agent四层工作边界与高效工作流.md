# 速览

## 一句话主旨

视频提出项目文件夹、对话、子 Agent或网页替身、Worktree四层工作边界，分别用于沉淀项目经验、管理单次任务、隔离重推理工作和并行开发方案，帮助降低上下文混乱、资源浪费与文件冲突。

## 核心要点

- 项目文件夹是长期工作的“办公室”，用于沉淀项目规范、规则和记录，并集中管理脚本、工具、素材等固定工作环境。
- 对话是当前任务的“工单”；长对话会持续压缩上下文，增加信息失真和出错概率，适合在任务阶段变化或对话过长时及时交接并开启新对话。
- 子 Agent或网页替身的核心价值是上下文隔离，可将资料搜索、调研和方案分析等重推理任务交给外部处理，只把结论带回主流程。
- 常规对话和指令执行可由主 Agent直接完成，而重推理任务交给网页端处理，可以减少主 Agent的上下文和额度消耗。
- Worktree为并行对话或方案提供独立的项目副本，避免多个任务同时修改同一项目文件时发生冲突和覆盖；完成后再将最佳结果合并回主项目。
- 四层边界可以串联成完整工作流：先建立项目文件夹，再按工序分配对话，将重任务外派，多方案并行时使用Worktree隔离。
- 视频的核心观点是，AI Agent长期使用后的瓶颈不一定是模型能力，而可能是工作边界不清导致的流程混乱；划清边界后，Agent才能更稳定地协作。

# 视频原文

AI Agent 越用越乱？先划清四层工作边界

使用 AI Agent 时，最常见的问题不是模型能力不足，而是工作边界模糊。视频提出了一个清晰的四层边界框架，帮助用户系统性地管理 Agent 的工作流程，避免混乱和效率低下。

四层工作边界概览

这四个边界从宏观到微观，共同构成了一个有序的工作环境。

边界层级 核心作用 类比
项目文件夹 沉淀经验，固定环境 办公室
对话 管理单次任务流程 工单
子 Agent / 网页替身 隔离脏活累活 外派员工
Worktree 隔离并行方案 独立沙盒

边界一：项目文件夹 (Project Folder)

项目文件夹是长期工作的“办公室”，它解决的不是“能不能访问”，而是“工作如何进行”。

沉淀项目经验：将项目的规范、规则、记录等文档化，方便新 Agent 快速上手。
固定工作环境：将项目所需的脚本、工具、素材等集中管理，让 Agent 进入时就能直接开始工作，无需从零配置。

边界二：对话 (Conversation)

对话是当前处理的“工单”。即使是同一件事，也不宜在一个对话中拖得太久。

问题：长对话会导致上下文反复压缩，信息失真，任务出错概率上升。
解决方案：及时交接，开启新对话。作者开发了一个交接 Skill，能自动提醒并整理工作进展，无缝开启新对话，避免信息丢失和重复劳动。

边界三：子 Agent / 网页替身 (Sub-Agent / Web Proxy)

直接使用子 Agent 成本高。其核心价值在于上下文隔离，让“脏活累活”在外部完成，只将结论带回主流程。

作者借鉴此思路，为自己的 Agent 开发了“网页替身”Skill，实现了任务的自动化分流，有效利用了不同客户端的额度。

任务类型 处理方式 优点
资料搜索、调研、方案分析等重推理任务 自动交给网页端处理 隔离上下文，节省主 Agent 的额度和资源
常规对话、指令执行 主 Agent (如 Code Interpreter) 直接处理 保持主流程的简洁和高效

边界四：Worktree

当多个对话或方案需要同时修改同一个项目文件时，很容易发生冲突和覆盖。

作用：为每个对话或方案创建一个独立的项目副本（沙盒），让它们各改各的，互不干扰。
使用时机：仅在需要多方案并行开发时启用，最后将最佳结果合并回主项目。

总结：一个完整的工作流

将这四层边界串联起来，就形成了一个高效有序的工作流程：

建项目：为长期工作创建项目文件夹，固定规则和工具。
分对话：不同工序或长时间工作要及时交接，开启新对话。
派任务：将资料搜索等重活交给“网页替身”处理，只带回结论。
并行试：多方案并行时，用 Worktree 隔离，避免文件冲突。

核心观点：AI Agent 用久了真正的瓶颈不是模型能力，而是边界不清导致的混乱。把边界划清楚，Agent 才能越用越顺。
