# 速览

## 一句话主旨

视频通过架构、消融实验、记忆表示、模型位置、解锁机制和技术栈六个维度，对比 TencentDB Agent Memory 与 NylonME，主张原文与抽象双层共存、图关系联想和可回退的记忆引擎设计。

## 核心要点

- TencentDB Agent Memory 以 LLM 推理上下文为中心，将记忆卸载、分层存储并在推理前注入，核心价值是减少 Token 消耗；NylonME 则让输入先经过记忆引擎进行情境共振，再交给 LLM 推理，并将结果回写记忆。
- 视频提到的消融实验显示，只保留大模型提炼的抽象层会使分数下降 3.4 分，因为压缩可能损失某些问题所需的细节；NylonME 的方案是让叶子层保留逐轮原文、抽象层保存提炼事实，双层同时参与解锁。
- TencentDB 的四层模型强调垂直分层、独立替换和可追溯；NylonME 使用六丝图模型，通过关系边显式连接记忆，形成有向有权图，并提供双粒度上下文网络。
- 两套方案都使用大模型处理记忆，但 TencentDB 将其放在压缩管道中，NylonME 则让大模型负责结构化提取、冲突检测和抽象，并在大模型不可用时回退到启发式规则。
- TencentDB 使用 BM25、向量检索和 RRF 融合；NylonME 进一步使用图扩散、包含时间衰减、情感强度和频次加成的张力打分，以及按问题类型调整扩散深度和向量重排。
- 技术栈方面，TencentDB 使用 Python 与 SQLite，适合快速集成；NylonME 使用 Rust 内核，将图结构和向量索引嵌入进程，视频给出了写入 TPS 12494、百万节点内存 720MB 的指标。
- 视频认为两者并非简单分高下：Python 团队快速集成可选择 TencentDB，对内存、延迟和吞吐有硬性要求的团队则可考虑 NylonME，最终效果仍需由时间、市场和公开复现验证。

# 视频原文

国内AI Agent的记忆赛道目前有三股力量最值得关注。第一个，Memos学术先行。腾讯云的TencentDB Agent Memory大厂出品，GitHub九千三百多星，工程实用主义的代表作。还有我们在造的NylonME，Rust的原生六丝记忆模型，情境共振解锁。
这条视频单刀直入，NylonME和腾讯的方案到底有什么本质不同？这一次我们带实验数据来。
最根本的分歧是架构哲学，以谁为中心？腾讯的架构是LLM推理上下文，卸载记忆，分层存储，下次推理前注入记忆，在LLM的外围工作。核心价值是给LLM省token，厂商自测能省百分之六十一以上，这个能力是实打实的。
NylonME的架构是输入先经过记忆引擎做情境共振，再交给LLM推理，推理结果回写记忆。记忆在LLM的前面，LLM是记忆引擎的推理外设。一句话，腾讯方案里记忆是一个被LLM调用的工具，NylonME方案里记忆是驱动推理的上下文引擎。
第二个分歧要用实验说话。腾讯的四层模型有一个隐含假设，信息可以逐层压缩，压缩后的高层表示可以替代低层细节参与推理。我们本来也准备这么干，直到消融实验给出了答案。只保留大模型提炼的抽象层，分数不但没涨反而掉了三点四分。原因不复杂，压缩是有损的，丢掉的细节里总有一部分恰好是某些问题的答案。
正确的解法是双层共存，叶子层保留逐轮原文，抽象层保存提炼事实，两层同时参与解锁四类问题，全面超过基线。再配上自适应联想深度和向量重排，我们把LOGO全量成绩从磁面基线的百分之四十七点一一路推到了百分之八十四点六七，十七点五分的提升里，每一分都有对照实验。
这组实验的启示不是分层错了，是分层替换错了。原文不能只留在事后追溯的角落里，它必须留在解锁通路上。
第三个分歧，记忆表示：分层树还是图网络。腾讯的四层模型是行业内最细致的分层设计，每一层独立可替换，数据可追溯，白盒可读。但结构性代价是层级之间是垂直的，横向没有关联。用户喜欢靠窗座位，和用户上个月去了东京是两条孤立的记录，它们之间的关联只能靠大模型在解锁时临时推断。
NylonME的六丝图模型走了另一条路，记忆与记忆之间通过关系边显式连接，不是分层树，是一张有向有权图。再加上双层写入，大模型拿到的是一个已经组织好的双粒度的上下文网络。
第四个分歧，大模型的位置。两家都用大模型处理记忆，但位置完全不同。腾讯的大模型在压缩管道里，负责把对话压缩成分层表示，目标是省token。
NylonME的大模型在引擎内部做三件事：编制、分解、写入时提取结构化的六丝要素；冲突检测，用户上周说不吃辣，这周说无辣不欢，不会被寂寞覆盖；绘画即抽象，绘画结束时自动提炼。还有一个关键的设计约束，大模型是增强，不是依赖，大模型端点不可用时引擎自动回退到启发式规则，核心读写路径不受影响。我们不认为一个记忆引擎应该因为大模型挂了而挂。
第五个分歧，解锁机制。腾讯用BM25加向量加RRF融合，业界标准做法，成熟可靠。但两个老问题依然回答不了。第一，和当前情境有关联，但关键词不匹配的记忆怎么召回？用户问最近网有点卡，如果记录里没有“网卡”这些关键词，这条宝贵的故障记忆就沉底了。图扩散可以从词面命中“延迟”，激活“延迟”敏感标签，沿关系边扩散到历史工单。
第二，十条相关记忆里哪条最重要？怎么排序？NylonME是三段式张力打分，编码时间衰减、情感强度、频次加成，然后按问题类型自适应扩散，细节类零跳，推理类最多四跳。最后查询向量余弦重排。解锁策略应该随问题类型变化，这一点在公开的同类项目里还没看到有人做。
第六个分歧，技术栈。腾讯是Python加SQLite，一个pip install就能跑，零依赖的设计非常聪明，这是它九千多星的重要原因。
NylonME走了另一个极端，Rust写内核，图结构和向量索引全部进程内嵌，翻译出来就是一个二进制文件，比pip install还轻，写入TPS12494，百万节点内存720兆。
这里没有谁更好，只有谁更适合你的技术栈。Python全站团队快速集成选腾讯方案，对内存延迟、吞吐有硬性要求的团队，NylonME是更好的底材。
最后，把两家放在一起比不是要分高下。坦率的说，腾讯团队在工程执行上仍然比我们成熟得多，九千三百行不是白来的。但这一周的实验让我们对第一版的那句直觉有了数据：总有一些东西压缩会丢掉，而丢掉的东西在某个情境下恰好是关键信息。
记忆不该只是大模型的附属品，智能体真正需要的是一个会联想、会遗忘、会检测矛盾，能在原文与抽象之间自由穿行的记忆系统。两条路径最终会通向两种不同的产品形态，哪个对，交给时间和市场去验证。
NylonME开源在GitHub，评测脚本随仓库公开，欢迎来拍砖，更欢迎来复现。
