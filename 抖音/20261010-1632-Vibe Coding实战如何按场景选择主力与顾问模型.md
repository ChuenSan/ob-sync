# 速览

## 一句话主旨
按 Vibe Coding 的实际场景选模型：长程编码看通过率与成本，前端看社区盲测观感和能力成本曲线，综合智力指数不作为主要依据。视频把 GM 5.3 Flash 定为主力编码模型，把另一家厂商的 Kimi K3 定作顾问，用来先定前端 UI 规范；具体名单会过时，按场景和曲线选的思路不变。

## 核心要点
- 视频强调模型要按实际场景选，而不是脱离用途只看综合排名。以这期 Vibe Coding 实战当时的场景，讲述者认为基本可用 GM 5.3 Flash，但仍完整走一遍选型流程。
- DeepSWE 用来看长程编码任务。图的纵轴是通过率，横轴是花费成本，越靠近右上角性价比越高。视频据此认为，当时能当主力模型的是 GPT Luna，或 GM 5.3 Flash。
- 顾问模型建议换一家厂商，选用 Kimi K3。视频称它在前端目前是 T0；这次做的是会涉及页面开发的外部项目，因此用 Kimi K3 先定 UI 规范，再让 GM 5.3 Flash 开发，以兼顾性价比和质量。
- 第三个榜主要比「好不好看」，名次由社区用户盲测投出。视频称生成图片、视频也要看这个榜，图像方向目前是 GPT two 领先；这次的外部前端场景里，Kimi K3 排第一。
- 日常若主要是前端画页面，就看「能力与成本」那条线，越靠左上角性价比越高，并优先从绿色区域选择。视频点名的模型有 Kimi K3、GML 5.3、Gemini 3.7 Flash、GM 5.3 Flash、M2.5，以及 DeepSeek V4 Flash 的 0731 版本。
- M2.5 会排到这个位置，是因为要按细分场景选。视频称在 Coding 场景下，有没有单独针对性训练差别很大，M2.5 和 Kimi K3 的前端都是单独拉出来优化的。力大砖飞和水桶模型两种做法各有优劣，由厂商自己权衡。
- Artificial Analysis 的智力指数不用太在意，视频称它不是针对 Vibe Coding 的，主要看成本。这张图同样是越靠左上角性价比越高，成本优先就选绿色区域里的模型。视频认为这类场景看上述三个排行榜就够了。
- 模型迭代很快，选择结果有时效。视频称如果过了一个月才看，这期给出的具体答案一定会变，但选模型的思路不变。这期定下的主力编码模型是 GM 5.3 Flash，顾问模型是 Kimi K3；下一期再做编码选型。
