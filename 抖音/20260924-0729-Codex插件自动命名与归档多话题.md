# 速览

## 一句话主旨

视频介绍一个用于 Codex 的话题管理插件：根据最近对话自动生成包含工作类型、对象和目标的标题，并通过 Hook、Python 脚本和 App Server API 完成改名，同时按闲置时间自动归档长期未使用的话题。

## 核心要点

- 当 Codex 中的项目和对话话题增多时，原生标题不直观，用户可能难以在多个项目中快速找到需要继续的对话；该插件的目标是提升并行项目下的话题可检索性。
- 插件会按照工作类型、具体对象和任务目标组织标题，并在前面加入 Emoji 分类标识，使视频制作、开发、调研等不同类型的话题更容易区分。
- Codex 的对话结束流程会触发 Hook；Hook 完成后调用插件中的 Python 脚本，结合最近几轮对话和用户输入生成新的话题名称。
- 视频介绍的实现会调用 Codex CLI，让模型在较低思考程度和快速模式下判断命名结果，再通过 Codex App Server 提供的 API 修改当前话题标题。
- 由于标题生成只需要处理较少的上下文和简短输出，视频认为这种方式响应较快、Token 开销较低，适合在每次对话结束后自动执行。
- 插件安装后会创建每天上午十点运行的定时任务：话题闲置十四天时，先交给模型判断工作是否已经完成；如果已完成且用户尚未归档，则自动归档，闲置三十天后则直接归档。
- 使用者可以将插件路径交给 Codex，并让 Codex 代为安装；安装完成后，左侧话题列表会更清晰地反映当前工作内容和所属项目。
