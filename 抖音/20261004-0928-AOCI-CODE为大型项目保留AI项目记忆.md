# 速览

## 一句话主旨

视频介绍北大开源项目 AOCI-CODE 如何把代码模块、接口契约和依赖关系整理成随代码更新的项目索引，帮助 Codex 与 Claude Code 在重开会话、切换模型或处理大型项目时延续项目认知，并展示其在质量测试、跨模块排错和多 AI 协作中的应用。

## 核心要点

- 视频将 AI 在长时间对话中偏离主题、重复犯错的现象称为上下文腐化（Context Rot），并提到上下文使用率达到 70% 以上时可能出现跑偏，此时常见做法是压缩或重开对话，但前者可能丢失细节，后者需要重新理解项目。
- AOCI-CODE 被描述为一份会随代码同步更新的项目交接手册：它提炼各模块的作用、接口契约和依赖关系，整理成与代码版本绑定的项目索引，而不是把完整聊天记录直接塞给 AI。
- 借助项目索引，AI 在会话重开或从 Codex 切换到 Claude Code 后，可以先读取项目结构，再检查相关源码，从而了解已有改动和当前需要修改的位置。
- 视频展示的软件开发质量测试中，DeepSeek V4 Flash 裸跑得分为 71.49，接入 AOCI-CODE 后为 77.7；DeepSeek V4 Pro 裸跑得分为 73.83。视频据此认为，项目认知更完整准确可以提升模型的工程交付表现。
- 使用时可将 GitHub 链接交给 Codex 并让它按说明安装；重启后，AOCI-CODE 会扫描整个项目建立基线，后续代码和需求发生变化时更新项目认知地图。
- 视频用一个十万行电商系统的待支付订单 Bug 举例：通过索引追踪支付回调、订单微服务和数据库落库链路，最终定位到新支付渠道字段改名导致订单状态没有更新。
- 在优惠券功能开发案例中，Codex 完成基础开发后遇到横跨购物车、商品、核销规则和结算中心的问题；视频描述另一款 AI 工具基于同一份索引找出后端结算缺少二次校验的原因并给出重构方案，再由 Codex 执行修改和补充单元测试。
- 视频总结，AOCI-CODE 的核心价值是把项目认知长期保留下来，使会话可以重开、模型可以切换，并帮助 AI 沿着索引处理大型长期项目中的跨模块 Bug 和复杂功能。

# 视频原文

Vibe Coding久了，我最怕的就是Codex突然来一句：你说的对。这多半不是因为没有说明白需求，而是它已经开始忘记规则，偏离主题、重复犯错。这种现象就是上下文腐化「Context Rot」，AI正在掉进降智区「DumbZone」。无论是Codex还是Claude Code，一般上下文用到70%以上就会跑偏，这个时候要么把对话压缩（/compact），但有可能丢细节，要么直接重开（/clear），但AI要重新理解整个项目。难道就没一种更优雅的解法，既能让上下文保持干净，又能长期保留重要知识点？我发现了一个神奇的项目，北大研究源开源的「AOCI-CODE」，专治这个痛点。简单来说，你可以把「AOCI-CODE」理解成一份会跟着代码同步更新的项目交接手册，它不会把聊天记录一股脑塞给AI，而是把每个模块的核心作用、接口契约、依赖关系提炼出来，整理成一份和代码版本绑定的项目索引。这样一来，不管是上下文爆了重开会话，还是Codex无缝切换到Claude Code，AI都不用从几万行代码开始重新学习。它先读一遍结构索引，再去检查相关源码，很快就知道之前改了啥，这次该动哪。实际效果怎么样？在软件开发质量测试中，「DeepSeek V4 Flash」裸跑是71.49分，挂上「AOCI-CODE」直接飙到了77.7分，反手就干翻了「DeepSeekV4 Pro」裸跑的73.83分。更绝的是，用8种运行模式横向对比测试，Flash加「AOCI-CODE」，模型本身没有变，只是获得了更完整、更准确的项目认知，最终的工程交付能力就能直接跨过一个段位。「AOCI-CODE」要怎么用？其实很简单，把GitHub链接直接甩给Codex，让它照着说明的那完成安装。重启之后，「AOCI-CODE」会先地毯式扫描整个项目，建立基线。后续你的代码和需求只要发生变动，这份认知地图就会自动更新。我自己经常用到的两个场景：第一个接手大体量项目，排雷修Bug。比如这个10万行代码的电商系统，线上报了个离谱的Bug，用户真金白银付了款，订单页面却卡在了待支付。换作以前，Codex得在支付、订单、DB、MQ各种模块里大海捞针，但是挂上了「AOCI-CODE」后，它一眼就能从索引里看透整条链路，支付平台回调之后走了哪个接口，到了哪个订单微服务，最后在哪一步落库。按图索骥去扒代码，秒接定位。破案了，是新接入的支付渠道字段改了名，导致状态没有被刷进去。第二个多AI轮番上阵，丝滑接力协作。比如我要给这个电商系统开发一个优惠券功能，先让Codex把前端、数据库、结构和基础API撸完，结果一测结算，翻车啦。这种问题横跨购物车、商品系统、核销规则和结算中心，Codex左右互搏了几轮，脑子明显开始打结。我反手切换到了更聪明的Cloud Code，因为底层啃的都是同一份「AOCI-CODE」索引，Fable5顺着索引一瞄最新改动，直接揪出根因，后端结算漏了二次校验，顺手递出了重构方案，再扔给Codex执行，补单元测试，一键收尾。这就是「AOCI-CODE」最硬核的价值，会话随时可以重开，模型可以随时更换，但项目记忆不会归零。过去Codex面对几万行、十几万行代码的复杂项目，很多时候真不是它水平不行，而是一个上下文根本装不下整个项目的前因后果，每次都要手动复制代码，粘贴报错，再像复读机一样把背景重新讲一遍。「AOCI-CODE」把这层项目认知长期保留下来，以前AI啃不动的跨模块Bug和复杂功能，现在可以沿着索引更快定位，继续推进。如果你也在维护一个长期项目，强烈建议把「AOCI-CODE」跑起来，省下的绝对不是几次全局搜索的时间，而是让AI真正具备了接管大型长线项目的工程能力。
