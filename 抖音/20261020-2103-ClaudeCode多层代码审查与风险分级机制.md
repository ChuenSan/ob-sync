# 速览

## 一句话主旨
视频介绍了 AI 参与代码审查的多层机制，包括多智能体并行审查、自动化检查、按风险分级的人工作出批准，以及用评测和轮数上限改进审查器；视频称该机制提升了审查覆盖与交付效率，同时降低回滚比例。

## 核心要点
- 视频称 Claude Code 生成的代码约占九成；几个月内合并的 PR 翻了一倍多，而需要回滚的比例下降了四成以上。
- 代码改动通过多层检查，大部分由自动化流程完成；各层可能漏检，因此还依赖快速回滚处理穿透检查的问题。
- 每个 PR 会由多个智能体并行审查并查找 Bug，再通过投票决定是否通过；视频称获得实质性意见的内部 PR 比例从16%升至54%。
- 人工审批按风险分级：低风险改动无需人工批准，普通改动需一人批准，最高风险改动需两人批准；智能体批准不能替代人工批准。
- 团队将过去引发事故的 PR 制成评测集，定期运行审查器，并对每次改动进行打分，以持续改进审查效果。
- 为避免智能体互相审查导致循环，团队给审查设置轮数上限；视频称一轮通过的比例从65%升至78%。
- 人的工作重点转向判断高风险代码与架构决策是否应当实施、审阅证据并为结果负责；理解代码时，也可以让 Claude 生成当前代码的讲解。
- 视频总结，审查并未取消，而是把大部分代码阅读交给机器，目标是减少每次改动所需的人工时间，同时不增加回滚。

# 视频原文

cloud code自己的代码大约九成是cloud写的，产出这么快还有人逐行审吗？出了问题谁都抵。几个月里合并的pr翻了一倍多，需要回滚的比例反而降了四成以上。秘诀是阅读交给机器人的注意力，留给真正需要人的地方。审查不再是最后一道关卡，更像拼写检查一直在跑。一个改动到用户手里要过好几层检查，大部分是自动的，就像几层带孔的板子，每层都会漏，但很少有问题能穿透所有层，漏网的靠快速回滚。每个pr都先让cloud审多个智能体并行找bug再投票，多数认可才发出来。拿到实质性意见的内部pr从百分之十六涨到五十四。人工批准按风险分级，低风险不需要人，普通改动一个人最高风险两个人，而且智能体的批准永远顶替不了人。审查器也在进步，过去引发事故的pr做成评测级，每天跑审查器，每次改动都拿它打分。但智能体互相审可能没完没了，有个pr一夜改了五十多轮，于是加了轮数上限，一轮就通过的比例从百分之六十五升到七十八。人的工作转向机器不擅长的决定该不该做高风险代码架构，看懂证据以及为结果负责。怎么了解代码？想懂哪一块就让cloud写份讲解，几分钟搞定，反映的还是代码现在的样子。一句话总结：审查没有取消，只是大部分阅读交给了机器，目标是每个改动花更少的人工时间，回滚却不比以前多。
