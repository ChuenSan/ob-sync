# 速览

## 一句话主旨

视频以图搜图为例，介绍 Milvus 向量数据库从向量与标量检索、Segment/Partition/Collection 数据组织，到存算分离、读写分离、协调调度和高可用的架构设计，并串联写入、向量混合查询与主键查询流程。

## 核心要点

- 文本、图片、视频和音频都可以转换为向量；向量数据库通过比较向量距离，从海量数据中检索语义或内容相近的结果，同时也可按数字、字符串等标量字段过滤。
- 视频将标量索引与向量索引作区分：标量字段可使用 B 加数倒排索引，向量字段则使用 HNSW、IVFPQ 等 ANN 索引方案；两类索引配合过滤并取交集。
- Segment 是数据存储的逻辑单元，向量列、标量列及索引文件分别组织。Growing segment 接收新写入，封存后成为不再接受写入的 sealed segment；小 Segment 可通过 compaction 合并。
- Partition 按业务维度对 Segment 分组，Collection 则将一个或多个 Partition 组织为逻辑表；视频以图片、文本和视频数据的检索需求说明划分 Collection 的作用。
- 分布式架构通过对象存储承载数据与索引，并让计算节点按需加载；Data Node、Query Node、Index Node 分别承担写入、查询和索引构建，Proxy 接入请求，Coordinator 管理调度与元数据。
- 视频描述的高可用方案包括写入链路上的消息队列与消费 Offset（并称其为 WAL），查询侧的 Query Node 多副本，以及 Coordinator 故障后的切换。
- 图像写入流程包括编码生成向量、Proxy 写入消息队列、Data Node 写入 Growing Segment、封存并落到对象存储、构建索引及 Query Node 加载；读取则可并发执行向量与标量混合查询，或按主键索引查找记录。
