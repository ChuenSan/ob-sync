# 速览

## 一句话主旨

作者通过每天浏览 GitHub Trending 和 Product Hunt，将技术能力的变化与市场关注、用户反馈结合起来：前者观察新能力与基础设施，后者分析产品定位和价值表达，以持续更新对产品趋势与机会的判断。

## 核心要点

- 作者表示每天用约一小时浏览 GitHub Trending 和 Product Hunt，分别观察技术趋势与用户市场，作为产品经理判断方向的两个坐标。
- 产品经理看 GitHub Trending 的重点不是代码细节，而是近期项目集中出现的方向、快速升温的领域，以及哪些能力正在成为新的基础设施。
- 作者以 AI Agent 和自动化工作流项目集中出现为例，将其视为技术能力成熟、新产品形态可能具备可行性的信号，并关注其对现有产品与用户预期的影响。
- 作者通过 openclaw 定时推送项目，按标签、star、创建日期等筛选，每天获取十五到二十条项目，再阅读 README、试用产品或克隆运行感兴趣的项目。
- 作者还会让 codespaces 绘制产品核心架构图，辅助理解产品，而不只停留在阅读项目介绍的层面。
- 浏览 Product Hunt 时，作者先看榜单中正在冒头的产品类型，再选一两个与自身行业相关或表达特别好的产品，分析排名、标题、卖点与首屏价值展示。
- 对选中的产品，作者重点考察服务对象、解决的问题、能否用一句话讲清价值，以及评论中的集中反馈，以理解用户愿意买单和抱怨的内容。
- 作者认为，两平台结合有助于观察技术能力如何被包装为用户接受的产品，并持续区分新机会、短暂热点、技术成熟与逐渐明确的需求。

# 视频原文

我现在基本上每天都会做的一件事情是逛github trending和product hunt，每天差不多一个小时左右。这两个平台一个偏产品趋势，一个偏用户市场，刚好组成了产品经理每天判断方向的两个坐标。

github trending主要是帮我看技术世界目前正在长出什么样的一些新的东西出来。product hunt是帮我看用户市场现在在讨论什么，在关注什么，在买单什么。看这两个是让自己保持能够跟上ai时代产品技术的趋势。

先说github trending，很多人会觉得这不是程序员看的吗？其实不是。对产品经理来说，github trending不是为了看代码细节，而是为了看比如最近大家到底在做什么，什么方向正在快速升温，哪些能力正在变成新的基础设施。

比如说某段时间ai agent或者一些自动化的工作流，这些项目突然集中冒出来，这说明了什么？说明技术能力成熟了，说明新的产品形态可以开始具备可行性了。这个时候产品经理就要警觉了：这会不会影响到我的产品，会不会带来一些新的结构性的机会，会不会改写用户的预期。

我每天看github trending的方法也很简单，我通过openclaw每天定时推送给我，我会按照标签、star、创建日期等去筛选，每天会返回给我十五到二十条的项目。我除了看readme、试用产品之外，我还会把我感兴趣的把它给git clone下来，然后自己跑起来运行一下。现在通过cloud code或者codespaces其实是很容易做到的，甚至我还会让codespaces画个产品核心架构图给我看，这样子方便我更好的理解这个产品。

另外一个是product hunt。如果说github看的是技术能做什么，那product hunt看的是市场为什么愿意停下来。我每天看product hunt主要是为了训练产品感觉。我会看今天排名在前面的一些产品，它为什么能冲上去，它解决了什么问题，它的标题怎么写的，它的卖点怎么讲，它的首屏怎么展示价值，它的评论区里面用户愿意买单的是什么，用户抱怨的是什么。

一个产品能上product hunt往往不只是功能做出来，更重要的是价值表达清楚。这对产品经理特别重要，因为很多时候产品失败不是功能不行，而是需求表达不清楚、场景不够准确，或者是包装不够到位。

我每天看product hunt的方法也很固定：先刷它的榜单，看今天是什么类型的产品在冒头；再挑一两个跟自己行业相关或者表达特别好的产品，重点看其中的四个维度：它服务了谁，它解决了什么问题，它能不能用一句话讲清价值，以及用户评论里面的集中反馈是什么。

所以这两个平台我会一起看：github trending让我知道未来可能会在什么地方出现什么样的能力；product hunt让我知道这些能力最后会被包装成什么样的产品，并且被用户接受。

这件事的意义在于建立一种持续更新的判断力：比如说什么是新机会，什么只是一个短暂的热点，什么是技术正在成熟，什么需求现在变得越来越明确。

我觉得如果你也能长期坚持下来，你会发现自己对产品趋势、对用户和对产品机会的敏感度会明显不一样。
