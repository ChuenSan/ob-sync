# 速览

## 一句话主旨

视频对比了传统RAG与模块化RAG的基本流程，重点介绍模块化RAG如何通过查询改写、向量与关键词双路径检索、RRF结果融合和ReRank重排，提升检索的准确性与鲁棒性。

## 核心要点

- 传统RAG的基础流程包括文档清洗与分块、文本向量化入库、用户提问、向量相似度检索Top K结果，以及将上下文和问题交给LLM生成回答。
- 模块化RAG在传统流程上增加查询改写、关键词搜索、结果融合和结果重排等模块，用于处理口语化提问、专业术语匹配和单一路径检索遗漏等问题。
- 查询改写负责将口语化、意图不明确的问题改写为更专业、更能反映真实需求的查询；关键词搜索则通过倒排索引精确匹配业务领域术语。
- RRF分别汇总向量搜索和关键词搜索的结果，按照结果排名计算融合分数，公式大致为“分数 = 1/(rank + c)”，再按总分重新排序。
- 倒排索引的实现包括建立业务术语词典、记录文档块中的关键词并构建关键词到文档块的映射，以及通过关键词快速定位相关文档块。
- ReRank使用轻量级语义匹配模型对融合后的结果进行二次打分和排序，以进一步提高结果相关性。
- 视频将从传统RAG到模块化RAG的演进概括为增加检索维度和精度，并认为模块化RAG更适合复杂企业级应用场景。

# 视频原文

RAG技术解析：从传统到模块化

视频讲解了RAG（检索增强生成）技术的两种主流架构。首先介绍了流程简单的传统RAG，然后重点剖析了企业中广泛应用的模块化RAG。模块化RAG通过引入查询改写、关键词搜索、结果融合和重排等步骤，显著提升了检索的准确性和鲁棒性。

一、传统RAG：基础流程

传统RAG是最基础的实现方式，流程简单直接，是后续所有RAG技术的起点。

📄 文档处理：将原始文档进行清洗、分块。
📥 向量入库：将分块后的文本转换为向量，存入向量数据库。
❓ 用户提问：用户输入查询问题。
🔍 向量检索：将问题向量化，与数据库中的向量进行相似度匹配，获取Top K结果。
🤖 生成回答：将检索到的上下文和问题一起送入大语言模型（LLM），生成最终答案。

二、模块化RAG：企业级应用

模块化RAG是目前企业中应用最广泛、最成熟的架构。它在传统RAG的基础上增加了多个关键模块，以解决更复杂的检索问题。

核心流程

❓ 用户提问
✍️ 查询改写 (Query Rewrite)
🔍 双路径检索 (向量+关键词)
🔗 结果融合 (RRF)
🔄 结果重排 (ReRank)
🤖 生成回答

关键模块解析

模块化RAG的强大之处在于其各个模块的协同工作，每个模块都解决了特定的问题。

模块 核心作用 解决的问题
查询改写 将用户的口语化、随意的提问，改写为更专业、更能反映真实意图的查询。 用户提问不专业、口语化，意图不明确。
关键词搜索 利用业务领域的专业术语，通过倒排索引进行精确匹配。 向量搜索对专业术语不敏感，无法捕捉精确的业务关键词。
结果融合 (RRF) 将向量搜索和关键词搜索的结果进行综合排序，取两者的交集或并集。 单一检索方式可能遗漏重要信息，融合能提供更全面的结果。
结果重排 (ReRank) 使用一个轻量级的语义匹配模型，对融合后的结果进行二次打分和排序。 初步融合的结果可能仍有偏差，重排能进一步提升相关性。

三、技术细节：如何实现融合与重排？

结果融合 (RRF) 机制

RRF（Reciprocal Rank Fusion）是一种将不同来源的检索结果进行有效融合的算法。

分别检索：向量搜索和关键词搜索各自独立进行，得到各自的Top K结果列表。
计算分数：为每个结果项计算一个融合分数。公式大致为：分数 = 1/(rank + c)，其中rank是该结果在某一列表中的排名，c是一个常数。
合并排序：将所有结果项的分数相加，然后按总分重新排序，得到最终的融合结果列表。

关键词搜索的实现：倒排索引

关键词搜索依赖于倒排索引技术，这是一种成熟的信息检索方法。

建立词典
根据业务需求，建立包含专业术语的词典。

构建索引
为每个文档块，记录其中包含的关键词，并建立一个从关键词到文档块的映射关系（即倒排表）。

快速匹配
当用户查询中包含关键词时，可以直接通过倒排索引快速定位到相关的文档块，实现精确匹配。

四、总结与展望

从传统RAG到模块化RAG，核心的演进思路是增加检索的维度和精度。通过引入查询理解、多路径检索、结果融合和重排等技术，模块化RAG能够处理更复杂的业务场景，提供更可靠、更相关的答案，因此成为企业级应用的首选方案。
