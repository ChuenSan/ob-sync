# 速览

## 一句话主旨

视频围绕多 Agent 是否能共享 KV Cache 展开，区分默认独立推理、前缀缓存和语义缓存三种情况，强调共享的关键取决于 Prompt 前缀对齐、推理框架配置以及缓存是否命中。

## 核心要点

- 默认情况下，每个 Agent 的请求独立提交，推理引擎会分别计算并存储各自的 KV Cache；即使系统提示词相同，也可能在显存中保留两份重复缓存。
- 开启前缀缓存后，如果多个 Agent 共用同一套系统提示词和工具定义，推理引擎可以通过 Radix Tree 管理公共前缀，相同部分只计算一次。
- 语义缓存与 KV Cache 的前缀复用不同：缓存层会按历史问答对的语义相似度检索，新请求命中后直接返回结果，未命中才继续推理。
- 多 Agent 协作系统可以通过统一系统提示词、工具定义和 Prompt 顺序，提高公共前缀的缓存命中率，减少重复计算与显存浪费。
- 如果不同 Agent 的系统提示词顺序、工具定义格式或前缀内容不一致，前缀缓存可能无法命中，甚至出现开启缓存后速度更慢的情况。
- 面试回答应分情况说明：默认独立推理时不能复用；开启前缀缓存并完成前缀对齐后可以共享相同前缀的 KV Cache，此外还要区分语义缓存带来的结果复用。

# 视频原文

多个Agent能不能共用同一份kv cache？不能。每个Agent的推理请求都是独立计算的，为什么有的框架能让几个Agent共享同一段前缀缓存？这个你张了张嘴又没答上来。这个问题答案不是简单的能或不能，而是看你懂不懂Agent的推理背后的kv cache管理和前缀复用机制。这道题表面在问缓存能不能共享，实际上面试官想考的是你对推理加速、显存复用和多Agent的执行链路的理解。如果这道题你也不会回答，我整理了让大厂面试官沉默的必考题库，包含大模型基础面试、r&a、g、w、t、transformer、deep sec、Agent的项目方案面试题等等。只要我粉丝留下111，直接打包带走。做Agent的系统到底怎么判断两次推理能不能共享缓存？很多人脑子里只有一个粗糙的印象，每个Agent的独立推理缓存不互通，但真实情况要细得多。是否共享取决于prompt前缀是否对齐，推理框架有没有开启前缀缓存，还取决于多个Agent之间有没有共用同一套系统提示词和工具定义。能把这层讲清楚，你的Agent的工程化功底就立住了。
- 先说默认情况下为什么不行？一个Agent要推理，本质上是把完整的上下文提交给推理引擎，引擎为这次请求单独分配kv cache，想存记录每一层注意力的key和value。默认规则下，两个Agent的请求各自独立，即使系统提示词一模一样，引擎也会分别计算两遍，显存里存两份完全相同的kv cache，这就是大家最常见的缓存浪费。所以在默认独立推理的场景下，答案确实是不能。但是这里有个关键的转折，推理框架提供了前缀缓存的开关，其中一个叫radx attention，主要解决的是多个请求共享相同前缀时，kv cache能不能只算一次的问题，这在高并发多Agent的场景特别有用，避免每个Agent都把相同的系统提示词和工具定义重新算一遍。
- 还有一个更核心的叫语义缓存，开启之后，多个Agent是真的可以复用同一份推理结果的。这时候缓存层会做一件事，把历史问答对按语义相似度缩影，新请求进来先查语义缓存，命中直接返回，不命中再走推理，相当于在框架层面就帮你做了一层结果复用。这个能力在真实项目里有什么用？意义非常大。像一些多Agent的协助系统，会统一系统提示词和工具scam，所有Agent共用同一套前缀，推理引擎用radix tree管理共享前缀的kv cache，相同部分只算一次。这样新请求进来，引擎直接命中缓存，前缀避免了每个Agent都从头计算系统提示词，也避免了显存里存多份完全相同的kv cache造成浪费。所以你看，能不能共享不是推理引擎不允许，而是默认每个请求独立计算，主动做前缀对齐和缓存配置，它就能行。也就在这，如果没做前缀对齐，每个Agent的系统提示词顺序不一样，工具定义格式不一样，缓存命中率直接归零，甚至比不开缓存还慢。这种问题在多Agent的协助批量任务处理时最容易踩到。所以面试的时候不能只回答能或者不能，标准的思路是先分情况。默认独立推理模式下，每个Agent的kv cache单独计算，单独存储，相同前缀也不会复用。但如果开启了前缀缓存这个配置，多个Agent是可以共享相同前缀的kv cache的，推理引擎用radix tree自动识别公共前缀，相同部分只算一次，常用在多agents协助的高并发服务里。最后点一句，判断能不能共享的本质是看prompt前缀是否对齐，推理框架有没有开启前缀缓存，加上语义缓存有没有命中，这样答就显得你是真的做过落地，而不是背书。这种Agent架构加推理优化结合的题，最容易暴露你是不是只停在表面。
