# 速览

## 一句话主旨

视频以 Codex 子 Agent 为例，说明主 Agent 如何拆分任务、并行调度和汇总结果，分析子 Agent 在效率、成本与上下文控制方面的价值，并总结适合并行与不适合分发的任务，以及自定义 agent、模型继承和 Skill 约束的使用注意事项。

## 核心要点

- 主 Agent 负责与用户对话、制定方案和分发任务，子 Agent 不直接与用户交流，只执行主 Agent 分配的工作并返回结果。
- 视频认为子 Agent 的主要价值包括并行执行提升效率、为简单任务选择更便宜的模型以降低开销，以及把代码执行过程与主 Agent 隔离以减缓上下文膨胀。
- 探索代码、联网调研、运行测试、分析日志和独立检查等任务适合并行分发；修改同一领域文件、必须串行的任务，以及权限、发布和删除等复杂敏感操作不适合交给多个子 Agent。
- 使用子 Agent 会增加任务提示、上下文读取和结果汇总等额外开销；多个子 Agent 重复读取相同规范或技能，也可能导致 Token 消耗增加。
- Codex 可以通过自定义 agent 配置不同角色，例如复杂任务执行者、代码执行者、探索者和 reviewer；视频还提到可以把简单任务交给成本更低的模型。
- 视频指出，主 Agent 调度子 Agent 时不一定遵循自定义 agent 中配置的模型和推理强度，可能继承主 Agent 的设置；可在提示词或 Skill 中明确要求传递 `agenttype`，以指定目标 agent。
- 子 Agent 可能继承主 Agent 的历史上下文；上下文继承与自定义类型发生冲突时，视频建议通过 Skill 明确调度规则，并控制何时继承上下文、何时使用独立上下文。
- 视频介绍了用 `default` 自定义 agent 拦截未传递 `agenttype` 的方式，以及 `team mode` Skill 对子 Agent 调度、复用和销毁的约束；当主 Agent 的思考程度调到 ultra 时，视频认为它会更积极地使用子 Agent。
