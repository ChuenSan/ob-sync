# 速览

## 一句话主旨

视频介绍了 Codex 默认关闭的 Memories 原生长期记忆系统，说明它如何从历史会话中提取高价值信息，经全局整理形成分层记忆，再在新会话中按需召回，并对比了 Codex Memories 与 Claude Code AutoMemory 的实现差异。

## 核心要点

- Codex 处理任务时依赖当前事实层、会话记录层、长期记忆层和持久指令层，其中当前事实动态获取且优先级最高，AGENTS.md 负责保存长期规则。
- Memories 通过“旧会话提取—全局整理—新会话召回”形成长期记忆闭环，重点保存结论、证据和流程等高价值信息。
- 提取阶段会定期扫描历史会话，识别并生成候选记忆；整理阶段由内部整理 Agent 将其组织为分层的记忆手册。
- 整理后的记忆主要包括 memory_summary.md、memory.md、rollout_summaries，以及可能保存可复用工作流的 skills 目录，并通过项目划分减少记忆污染。
- 新会话不会一次性加载全部记忆，而是先查找 memory_summary.md，再搜索 memory.md，必要时打开会话摘要、技能文件或回溯原始会话。
- 用户可以通过特定提示词管理全局记忆，包括开关记忆、查询参数、查看记忆库，以及增加、修改或删除记忆。
- 视频对比认为 Codex Memories 默认关闭、按全局记忆库存储并延迟处理；Claude Code AutoMemory 默认开启、按项目隔离并实时写入。
- Memories 可能包含错误或过期信息，不能替代永久会话备份；需要长期遵守的规则仍应写入 AGENTS.md。

# 视频原文

Codex 长期记忆系统 (Memories) 全解析

Codex 内置了一套名为 Memories 的原生长期记忆系统，但默认是关闭的。它并非简单地保存聊天记录，而是通过一套复杂的流水线，实现了“旧会话提取 → 全局整理 → 新会话召回”的完整闭环，帮助 Agent 更智能地利用历史信息。

一、Codex 的信息调用模型

Codex 在处理任务时，依赖的信息可以分为四个层次，它们共同构成了 Agent 的“知识库”。

层级 内容 特点
当前事实层 代码状态、配置文件、测试结果等 动态获取，优先级最高
会话记录层 所有历史聊天记录 完整备份，归档后很少直接使用
长期记忆层 Memories 系统生成的结构化记忆 核心，包含索引和内容
持久指令层 AGENTS.md 中的长期规则 稳定，自动加载到每个会话

二、Memories 运行三阶段

Memories 的工作流程可以概括为三个阶段，就像“制作卡片 → 编写手册 → 按需查阅”的过程。

第一阶段：从旧会话中提取

Codex 会定期扫描历史会话，识别并提取其中高价值的信息（如结论、证据、流程），作为“候选记忆”。

第二阶段：全局整理与分层

一个内部的“整理 Agent”会将候选记忆组织成一个分层的记忆手册，主要维护以下几个文件：

📄 memory_summary.md: 高密度摘要和导航，会被直接带入新会话。
📄 memory.md: 长期记忆手册，按项目划分，避免记忆污染。
📁 rollout_summaries: 保存具体的会话摘要、结论和证据。
📁 skills: 保存已固化的、可复用的工作流程（非必然产物）。

第三阶段：新会话中的召回

在新任务中，Codex 会按需查找记忆，而不是一次性加载全部内容。

1. 从 memory_summary.md 中寻找关键词。
2. 用关键词搜索 memory.md。
3. 打开相关的 rollout_summaries 或 skills 文件。
4. 必要时，回溯到原始会话记录。

💡 核心思想：记忆并非越多越好，而是越快越准越好。

三、如何管理 Memories

用户可以通过特定的提示词直接与 Memories 系统交互，进行管理操作。

打开/关闭全局记忆
查询当前记忆参数
查看当前记忆库
增加一条记忆
修改或删除一条记忆

四、Codex vs. Claude Code 记忆系统

Codex 的 Memories 和 Claude Code 的 AutoMemory 虽然功能相似，但在实现上有显著区别。

对比维度 Codex (Memories) Claude Code (AutoMemory)
默认状态 默认关闭 默认开启
存储范围 全局记忆库 按项目隔离
写入时机 延迟处理 实时写入
存储方式 数据库 + Markdown 纯 Markdown 文件
遗忘机制 自动淘汰（基于使用） 依赖用户手动维护

五、核心结论

Codex 的 Memories 是一个强大但复杂的工具。它通过分层索引和按需加载的方式，让 Agent 能够高效利用历史信息。但它并非完美无缺，可能包含错误或过期内容，且不能替代永久的会话备份。对于需要长期遵守的规则，仍应写入持久指令层 (AGENTS.md)。
