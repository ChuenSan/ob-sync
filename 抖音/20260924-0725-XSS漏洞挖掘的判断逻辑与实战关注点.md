# 速览

## 一句话主旨

视频从浏览器是否将输入内容解析为 HTML 的角度解释 XSS 判断逻辑，梳理标签、事件与执行内容的基本组成，并介绍不同输入位置、危险函数、用户交互场景和高频访问功能在漏洞挖掘中的关注价值。

## 核心要点

- 判断一个位置是否可能存在 XSS，核心在于浏览器是否会把用户输入当作 HTML 标签解析；如果输入被实体化，尤其是尖括号等关键字符被转义，通常意味着利用空间较小，但仍需结合特殊场景判断。
- 视频将 JavaScript 执行比作浏览器中的命令执行，并指出 XSS 可能带来隐私窃取和功能劫持等影响；定制化 XSS 还可能通过 WebSocket 等长连接形成持续交互，冒用用户执行功能操作。
- 常见 XSS 载荷由标签、事件和执行内容构成，视频以图片标签、错误链接和加载失败事件为例，说明三者组合后如何在特定事件触发时执行内容。
- 可控输入点所在的 HTML 位置会影响测试思路：输入位于标签属性内部时，通常需要考虑逃逸引号并闭合标签；位于标签外部时，则可以直接尝试插入标签结构。
- 实战中应尽可能扩大可控输入点的排查范围，重点追踪前端代码中把输入拼接到 HTML 的危险函数，例如 `innerHTML`；如果断点能够命中可控数据流，说明该功能值得进一步分析。
- 除了“见框就测”，还应优先关注能与其他用户或管理员交互、且允许内容展示的功能，如评论区、公告栏、网站反馈、文档和文章；这些场景通常具有较高访问频率和更大的影响范围。
- XSS 是围绕 JavaScript 与浏览器解析机制展开的漏洞类型，视频最后提到可通过整理不同标签和事件属性的测试组合来辅助学习与验证。
