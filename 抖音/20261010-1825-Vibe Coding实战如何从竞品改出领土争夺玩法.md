# 速览

## 一句话主旨
对照竞品改玩法：部件流改成兵种，拆掉唯一老家的 1v1 改成多方领土占领，娱乐性放到纯 benchmark 前面。资源要主动采集并运回最近基地，V0 基地先不能被毁，胜负用赛季积分。技术选型这期没做，留到下期。

## 核心要点
- 上一期完成了可行性分析和需求分析。这期原定要做技术栈选型并把玩法定下来，实际只做了玩法，技术选型因时间太晚留下。按 Vibe Coding 的做法，需求评审直接跳过，虽然常规是需求文档写完后逐条过评审。上期产物包括可行性报告、竞品，以及一份 PRD。
- 先分析竞品玩法，并看它的原始游戏和参数。视频称那是一个被阉割过的 scripts。它虽是 RTS，却不靠兵种区分，每个单位都一样，靠加装不同价格的部件做策略：移动部件多就跑得快，再配远程可以放风筝打近战。分析时用的 V4.1 Flash，思考和出 token 很快，看起来慢是因为在跑脚本。
- 竞品有两处要改：部件系统改成传统兵种；1v1 打爆唯一老家即胜，Elo 好算，适合 benchmark，但娱乐性不够。他想引入多方，例如 1v1v1，地图上有资源点和产兵基地，目标是占完所有点位，接近古代争霸。竞品更像星际那种高科技，自己更像古代战争。地形、视野和经济可参考；胜利目标或给模型的奖励一变，策略也会大变。
- 多方会让 benchmark 难做，Elo 不好算，场次也要很多，所以调整优先级。一开始想做带娱乐性的大模型 benchmark，但已有人做过，再做意义不大，就把娱乐性放前面。计分还想过淘汰加积分，具体规则要再设计。整体先定为领土占领加兵种。
- 生成玩法文档时换用视频里的加冒 5.3。前两问他认可，并说如果用 grow 时总是同意、没有分歧，就不必用这个技能。第三问反对被动收入，选主动采集：要在资源点采到并运回最近基地才能招兵，半路资源可能被打掉。放任模型发挥，容易改回被动收入，需要把双方不一致的地方对齐。这一问选 B。
- V0 基地先不被摧毁。其余细节可先定一版，但不要定死，做的时候可能调整。方向也从准备做 benchmark，改成不再重复已有作品。胜负用赛季积分。多方之后，出场次数、相邻对手、两两或三三组合不同，结果都会变，只能作参考，达不到 benchmark 的确定性，胜率波动更大。兵种以后再扩展。当时他认为这一轮主要改第三问。
- 第二轮追问更细，答完就让它停，这些等 V0 做出来再改。grow 仍可用来发现忽略的盲点。他不给基地被动收入，只给初始资金和初始兵；不会采集就该被淘汰或灭掉。农民种田算不算被动收入，先放下回头再想。农民占领被写成最快、约 2 倍，他认为不合理，要改。说不清会误判，讲太细没空间，讲太粗又会乱发挥。
- 答完后直接生成玩法文档，并改可行性分析及另一份前期文档，让三份不再冲突，因最初以 benchmark 为主。竞品参考文档删掉。提交换人，小王跑得太慢。玩法已大致定下，技术选型这期不做。AI 时代的选型或架构，本质是给 AI 搭反馈回路，后续都围绕它，概念留到实战讲。下一期做架构和技术栈、工具选型。
