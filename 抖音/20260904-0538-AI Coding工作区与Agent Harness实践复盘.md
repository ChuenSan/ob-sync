# 速览

## 一句话主旨

视频分享了在公司使用AI Coding和团队协作的实践过程：通过本地工作区、适配层、状态与交接文档，让不同Agent和会话持续承接任务；再通过渐进式加载优化上下文，结合Review和评测机制，逐步形成一套Agent Harness。

## 核心要点

- 最初采用单会话、单Agent的方式开发，切换Agent或新开会话后无法继承需求背景，导致重复解释上下文、阻塞并行开发和问题修复。
- 解决思路是把对话之外的工作状态沉淀到本地工作区，包括工作事项、过程、文档、状态和交接信息，使不同Agent能够继续同一项工作。
- 为适配不同Agent默认读取的规则路径，建立多Agent适配层，将各Agent的入口文档统一路由到核心的 Agent Guide，使切换Agent时仍能读取统一规范。
- 工作区按需求或事项拆分子工作区，并区分状态、归档和草稿；状态文档记录已完成内容、当前进度、待办和阻塞事项，交接文档帮助新会话快速确定下一步。
- 仅保存最终状态会丢失排查过程，例如无法说明为什么排除怀疑的A、B而转向C；过程性上下文仍需要通过适当方式沉淀，但不必记录所有对话。
- 在实践中，AI可以连续执行技术方案、Review、编码、本地测试、部署、集成测试、修复和汇报等环节，从而支持多个需求或工作事项并行推进。
- 长时间在同一组会话中持续开发、测试和迭代，会使上下文包含大量历史、工具输出、代码读取和默认规则；因此应采用渐进式加载，让Agent在正确时间读取完成当前任务所需的最少规则。
- 优化规范时不能只减少上下文，还要保持Agent原有的自主执行习惯，并通过快照、Review和测试等机制验证结果，避免AI声称完成但实际没有完成。
- 最终形成的Agent Harness包含适配、状态、交接、上下文路由和各环节Review机制，并可进一步向云端Agent和团队协作工作台发展。
