# 待提交文件检查

依据根目录 `CLAUDE.md` 实现的**只读初筛**工具。需要 Python 3.10+、Git，无第三方依赖；支持 macOS 和 Linux。

## 一条命令运行

在仓库根目录执行：

```bash
python3 scripts/pending_commit_audit.py
```

**本次只处理上次提交之后到现在的变化。** 历史未跟踪文件不会仅因未提交就成为本次候选。

终端先显示本时间段的“敏感风险优先”摘要，再将本次文件分为四类；时间待确认的变化另外列出，窗口外历史变化默认只显示数量。路径列表每类默认显示前 20 项，并明确提示省略数量：

| 分类 | 含义 |
| --- | --- |
| 本时间段待提交候选 | 时间符合要求且有 Git 变化，文本初筛通过，仍需人工确认用途和实际 diff |
| 本时间段需人工复核 | 疑似凭据、个人记录、附件、空文件、检查不完整等 |
| 本时间段应排除 | 私钥、本地配置、缓存、临时文件、个人敏感信息目录、Git 忽略文件等 |
| 无需重复提交 | 时间位于窗口内，但 Git 确认没有内容差异 |
| 时间待确认 | 删除/重命名等无法确定操作时间，或必要的时间无法获取；不计入本次候选 |
| 窗口外历史变化 | 不扫描内容，不计入本次候选；默认只汇总数量 |

**这些分类不是自动批准的提交清单，也不代表脚本修改过暂存区。** 已暂存的应排除项会单独警告；如果范围外或时间待确认的变化已暂存，会警告禁止直接提交，不自动取消暂存。

显示全部分类的路径（包括单独列出的历史变化，但不把它们变成本次候选）：

```bash
python3 scripts/pending_commit_audit.py --all
```

保存完整报告到仓库外（包含所有分类的路径、理由、命中类型和行号，不包含文件正文或凭据值）：

```bash
python3 scripts/pending_commit_audit.py --json "/tmp/obsidian-audit-$(date +%Y%m%d-%H%M%S).json"
```

报告使用独占创建：如果目标已存在则报错，不覆盖已有文件。默认不生成任何报告文件。报告仍包含个人文件路径，请勿直接公开；存放在 `/tmp` 中的报告可能被系统清理。

其他参数：

```bash
python3 scripts/pending_commit_audit.py --repo /path/to/vault --limit 5
python3 scripts/pending_commit_audit.py --max-mib 16
```

不指定 `--repo` 时检查脚本所在仓库，不依赖当前工作目录。`--limit 0` 等同于显示全部。

## 检查逻辑

1. 确认仓库根目录、分支、远程地址；获取 HEAD 的 **Committer Date** 和当前系统时间，输出完整日期、时间和时区。远程 HTTP 地址中的用户名/密码会隐藏。
2. 扫描文件 mtime 和 Birth Time。macOS 使用 `st_birthtime`，Linux 使用 `statx`；不可用时明确报告，不以 ctime 代替。排除 `.git/` 和常见依赖、缓存、构建目录的时间扫描。
3. 读取 `git status --porcelain -z --untracked-files=all`，用于验证实际变化及暂存范围；Git 状态总数不等于本次候选数量。窗口外历史变化只检查时间、汇总数量，不默认扫描内容。
4. 修改按 mtime 判断，新增可按 Birth Time 判断；历史未跟踪文件若近期实际修改，也可按 mtime 纳入。只有时间符合且存在 Git 变化的文件才进入本次内容检查；结合 Git 忽略规则及路径用途分类。没有 HEAD 时不套用窗口，按首次提交检查。
5. 检查工作区内容；对于已暂存变化，还检查**索引中的内容**，防止“工作区已脱敏、暂存区仍有凭据”的遗漏。分别检查已暂存与未暂存 diff 是否存在。
6. 检查私钥、常见 API Key/Token、认证配置、带凭据 URL 和部分个人信息模式；只输出风险类型和行号。示例凭据可能误报，其他凭据也可能漏报，不会联网验证任何凭据。
7. 删除、重命名/移动、复制的具体操作时间不能从 Git 状态获知，必须另列“时间待确认”；不使用文件旧时间或父目录时间推断。必要时间不可获取时也另列待确认。嵌套仓库仅汇总状态，不跨仓库批准文件。检查结束时再比对父仓库状态与 HEAD，发生变化则提示重新运行。

## 安全边界

- 不执行 `git add/commit/fetch/pull/push/restore/reset/clean`，不修改忽略规则或仓库文件。Git 命令禁用可选索引写锁；差异检查禁用外部 diff 和 textconv。
- 路径规则集中在 `pending_commit_audit.py` 的 `path_policy()` 中；个人信息目录、Obsidian 本地配置、YOLO 会话数据等规则针对当前仓库。其他仓库须复核这些规则。
- 二进制文件不做 OCR 或文档解析；非 UTF-8、超过大小上限（默认每份内容 8 MiB）、不可读内容均不能自动判定安全。符号链接不读取目标。嵌套仓库仅检查状态，不扫描其内部内容。
- 目录扫描错误、创建时间不可用和状态变化会明确报告。创建时间不可用且 mtime 在窗口外的新增文件不能自动纳入；不以 Git 的 untracked/added 状态代替时间证据。扫描不是文件系统一致性快照，扫描期间若仅内容变化、Git 状态码未变，也可能无法检测到。
- 无法自动判断所有隐私、版权、任务相关性及意外删除；提交前必须按 `CLAUDE.md` 人工检查 `git diff`、`git diff --cached` 及最终提交范围。
- 不检查远程是否有新提交。此工具不能替代 Push 前的 fetch、同步、冲突处理和验证流程。
- 正常完成退出码为 `0`，**不表示所有文件安全**；Git/文件访问等致命错误退出码为 `2`。风险项、部分扫描失败会在报告中提示，应检查输出，不只检查退出码。

```bash
python3 -B -m unittest discover -s tests -v
```

测试使用独立临时仓库，涵盖历史文件不纳入且不扫描内容、旧文件近期修改、新建文件保留旧 mtime、创建时间缺失、历史文件已暂存警告、暂存区凭据、删除/重命名时间待确认、忽略规则、嵌套仓库、符号链接、扫描上限及只读性等；不会修改当前仓库的 Git 状态。
